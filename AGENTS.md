# ConvertHub

Сервис конвертации файлов: JPG⇄PNG, DOCX→PDF, PDF→JPG. Веб-интерфейс и публичный API по ключу.
Файлы до 10 МБ, хранилище пользователя 300 МБ, API синхронный.

Монорепозиторий pnpm workspaces:
`apps/api` — NestJS 11 + Prisma + PostgreSQL · `apps/web` — Angular 20 standalone + Tailwind 4 · `packages/shared` — Zod-схемы, коды ошибок, лимиты

## Правила кода

- TypeScript strict. `any` запрещён — `unknown` и сужение.
- Валидация только через Zod-схемы из `packages/shared`. Константы не дублировать.
- Ошибки API — RFC 9457 (`application/problem+json`) с машиночитаемым полем `code`.
- Файлы никогда не пишутся на диск приложения напрямую — только через интерфейс `Storage`.
- Тип файла определяется по magic bytes, не по расширению и не по `Content-Type`.
- Angular: standalone, сигналы, `OnPush`. `NgModule` не использовать.
- Цвета, размеры, радиусы, отступы — только токены из `DESIGN.md`. HEX в разметке запрещён.
- Нужного визуального значения нет в `DESIGN.md` — спросить, а не подобрать самому.
- Каждый экран проверяется в обеих темах. Тёмная тема не получается инверсией светлой.
- Секреты только из переменных окружения.

## Чего не делать

- Не создавать репозитории поверх Prisma — Prisma Client уже репозиторий.
- Не писать DTO-классы руками и не подключать `class-validator` — тип берётся из `packages/shared` через `z.infer`.
- Не добавлять интерфейс с одной реализацией. Исключения ровно два: `Storage`, `ConversionEngine`.
- Не ловить ошибку, если с ней нечего делать — пусть летит в глобальный фильтр.
- Не отдавать Prisma-объект наружу как ответ API.
- Не писать комментарии, пересказывающие код.

## Протокол работы

> **Раздел заполняется владельцем проекта, не генерируется.**
> Это главный рычаг управления: правила выше говорят, *что* писать, протокол — *как себя вести*.
> Четыре вопроса, на которые он обязан ответить, каждый — проверяемым снаружи запретом:
>
> 1. Что предъявить **до** кода: план, поимённый список затрагиваемых файлов, названные альтернативы?
> 2. Что нельзя решать молча: добавление зависимости, изменение контракта API, отклонение от `plan.md`, создание файла вне заявленного списка?
> 3. Что делать при нехватке информации — спросить или выбрать умолчание? У обоих вариантов есть цена, правильного ответа нет. Выберите порог и запишите его.
> 4. Что считается «готово»: компилируется? критерии приёмки пройдены руками? дифф не содержит лишних файлов?
>
> Формулируйте запретами, а не пожеланиями: нарушение запрета видно в диффе, невыполнение пожелания не видно никак.
> Удалите эту рамку после заполнения.

## Критичные зоны

В этих местах ошибка не падает, а тихо открывает дыру. Здесь ИИ пишет план и ревьюит, **код принимается только после построчной проверки владельцем**:

- `apps/api/src/modules/auth/**`
- `apps/api/src/modules/api-keys/**`
- `apps/api/src/modules/conversion/validators/**`
- всё, что обрабатывает загруженный файл или сравнивает секреты

Спеки этих зон помечены 🔒 в `SPECS.md`. Инварианты аутентификации, обязательные к соблюдению при любой правке auth, — `AUTH-RULES.md` в корне.
