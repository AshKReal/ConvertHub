# Критичные зоны

Здесь ошибка не падает, а тихо открывает дыру. Функциональные тесты её не ловят: уязвимость — это то, что система делает **сверх** требуемого.

- Сначала план, потом код (см. `.claude/CLAUDE.md`); код принимается только после построчной проверки владельцем.
- Найдены **все** места, где данные попадают в систему, — не только основной путь.
- Сравнение секретов постоянно по времени (`timingSafeEqual`), не `===`.
- Тип файла определяется по сигнатуре (magic bytes), не по расширению и не по `Content-Type`.
- Имя файла от клиента нигде не используется как путь; ключ объекта генерирует система.
- Каждый `catch` вокруг парсера различает причины и ставит конкретный `code` — не единый `CONVERSION_FAILED` на всё.
- В лог не попадают: пароли, полные ключи, содержимое файлов, полные IP.
- Ошибка не раскрывает, существует ли объект или учётная запись (404, а не 403; одинаковый ответ на восстановление пароля).
- Ресурсы освобождаются в `finally`, а не только на успешном пути.

Полный чек-лист приёмки для 🔒-спек — `SPECS.md`, раздел «Для 🔒 — дополнительно».

Инварианты аутентификации (токены, OAuth, 2FA, rate limit, что нельзя логировать и возвращать) — `AUTH-RULES.md` в корне репозитория. При правках в `modules/auth/**` он обязателен к прочтению целиком.
