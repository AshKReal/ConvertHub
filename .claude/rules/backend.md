# Backend (NestJS)

- TypeScript strict, `any` запрещён — `unknown` и сужение.
- Валидация только через Zod-схемы из `packages/shared` (`ZodValidationPipe`), не `class-validator`.
- DTO-классы руками не пишутся — тип берётся через `z.infer<typeof schema>`.
- Репозиториев поверх Prisma нет — Prisma Client уже репозиторий.
- Prisma-объект не отдаётся наружу как ответ API (в строке есть служебные поля вроде `storage_key`).
- Ошибки — RFC 9457 (`application/problem+json`) с машиночитаемым полем `code`; не ловить ошибку, если с ней нечего делать, — пусть летит в `AllExceptionsFilter`.
- Файлы никогда не пишутся на диск приложения напрямую — только через интерфейс `Storage`.
- Модуль заводится, когда у него есть свой маршрут или своя сущность в БД. «На всякий случай» — не заводится.
- Модуль экспортирует сервис только если его вызывает другой модуль; прямой импорт файла из чужого модуля минуя `imports` — ошибка. `forwardRef` откладывает проблему, а не решает — двусторонняя зависимость модулей означает неверную границу.
- Абстракций ровно две: `Storage`, `ConversionEngine`. Интерфейс с одной реализацией не добавляется.
- `common/` — серверная инфраструктура; если тип нужен и фронту, его место в `packages/shared`, не в `common/`.

Структура модуля и слои — `ARCHITECTURE.md`, раздел 4.1.
