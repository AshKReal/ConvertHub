## Claude-специфика

- Перед изменениями в `apps/api/src/modules/conversion` и `apps/api/src/modules/auth` — сначала план, потом код.
- Новая сессия на каждую задачу из `tasks.md`. Длинная сессия после сжатия контекста теряет вложенные правила.
- Перед кодом по задаче из `tasks.md` — новая ветка от `main`, буквально: `git checkout main && git checkout -b NNN-slug`, а не от ветки предыдущей задачи. Имя — `NNN-slug` по номеру и слагу из реестра `SPECS.md` (например `004-error-contract`). Коммиты этой задачи — в неё, не в `main` напрямую: `SPECS.md` требует «одна фича — одна ветка — один PR». Если новой задаче нужен код из ещё не смерженной ветки — сначала смержить её (после подтверждения владельца), потом ветвиться от обновлённого `main`, а не стековать ветку на ветке.
- `git push` только после того, как владелец посмотрел диф и явно согласился. Коммит можно делать по ходу работы (это локальное состояние, не общий доступ), но пушить без подтверждения — нельзя.
- Правила с областью действия живут в `.claude/rules/*.md` с фронтматтером `paths`. В этот файл они не переносятся.
