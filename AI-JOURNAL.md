**Тесты 🔒-зон писал автор реализации — сознательное отступление от `TECH-SPEC.md` §15.** §15 требует, чтобы тест-кейсы придумывал не тот, кто писал код: иначе тесты кодируют то же непонимание и зеленеют при нерабочей системе. Смягчение, которое реально применялось: ассертить наблюдаемое поведение по кодам ошибок из `packages/shared`, не внутреннюю форму. **В настоящем проде так делать нельзя** — список случаев прозой должен приходить от владельца до того, как агент увидит код.

**Враждебное ревью тестов (`/code-review`, отдельный контекст) нашло 10 дыр, из них одна — ложно-зелёная по существу.** `guest-convert.spec.ts` проверял только `suggestedFilename()`, а имя файла зона загрузки собирает на клиенте из имени входа + `target`, не из ответа сервера — тест остался бы зелёным при сломанной конвертации (пустое тело, не тот формат). Исправлено: спек читает байты скачанного файла и проверяет PNG-сигнатуру. Вывод: «e2e прошёл» ≠ «фича работает», пока тест не смотрит на артефакт, а не только на то, что UI дошёл до финального экрана. ## 2026-09-02 · 016, 018 (стадия 10, ветка `docker`)

**Коммит `0673b65` (правки `REVIEW-FINDINGS.md` по ревью тестов) не попал в `main`** — PR #4 смержил `81e180a`, а этот коммит остался на удалённой `015-testing`. Не потеря: `git cherry-pick` в новую ветку `docker` первым коммитом. Причина, вероятно: PR открыли до пуша последнего коммита, GitHub смержил то, что было на момент открытия. Вывод: после `git push` последнего коммита в ветку убедиться, что PR действительно указывает на него, прежде чем говорить «готово».

**Dockerfile: `tsconfig.base.json` не был скопирован в build-стадию** → `pnpm --filter @convert-hub/shared build` внутри контейнера падал с сотнями `Cannot find name 'Map'` — `tsc` без `extends`-базы откатывался на `lib: ES5`. Локально не воспроизводится (база на месте). Ловится только реальным `docker build`. Урок: для монорепы в образ нужны ВСЕ файлы цепочки `extends`, не только манифесты пакета.

**`nest build` кладёт точку входа в `dist/src/main.js`, не `dist/main.js`.** Entrypoint был написан `node dist/main` (как в неиспользуемом `start:prod`-скрипте) → `MODULE_NOT_FOUND` при первом запуске контейнера. `rootDir` в `apps/api/tsconfig.json` не задан явно и выводится в `src`. Существующий `start:prod` в `package.json` тоже неверен — просто никем не запускается.

**`internal: true`-сеть Docker и published-порты несовместимы.** Задумка «Gotenberg в изолированной сети + порт на `127.0.0.1` для локального dev» не работает: контейнер только в internal-сети не получает проброс портов (Docker молча его игнорирует, `NetworkSettings.Ports` пуст). Пришлось выбрать: Gotenberg internal-only без порта (изоляция по `ARCHITECTURE.md` §2/§13), docx→pdf локально — только через `--profile full` или `docker-compose.override.yml`. Изоляция важнее DX для 🔒-спеки.

**MinIO нельзя поднять сервис-контейнером GitHub Actions** — `services:` не поддерживает `command:`/`args:`, а образ `minio/minio` без `server /data` просто печатает help. В CI-джобе `docker` MinIO поднимается отдельным `docker run` с ожиданием `/minio/health/live`.

**Отступление от одобренного плана, в диффе:** план требовал сделать `LOCAL_STORAGE_DIR`/`SIGNED_URL_SECRET` условно-обязательными через `superRefine`. Оставлены безусловными — условность протащила бы `string | undefined` в `signed-url.util.ts`/`local-disk-raw.controller.ts` (зона `critical-zones.md`), а это дороже, чем одна заглушка в `.env` при `STORAGE_DRIVER=s3`. Зафиксировано в `specs/016` → «Отступления от плана».

**Спека раньше кода — на этот раз наоборот, по процессу.** Для 016/018 сначала написаны `specs/016-*.md` и `specs/018-*.md` целиком (задача/входит/не входит/поведение/критерии/план/отвергнутые варианты), закоммичены гейтом `2a1d8eb`, и только потом код. Открытые вопросы 018 (Gotenberg в профиле?, health-проверка?, метрика?, Playwright?) были помечены в плане явно и разрешены при реализации с записью решения — не выбраны молча.
