## Задача

Разработчик, который хочет вызывать публичный API напрямую (не через веб-интерфейс), должен найти список эндпоинтов, формат ошибок и пример `curl` — без реальной OpenAPI-схемы, которой ещё нет (013).

## Входит

- Страница `/api-docs` — **публичная**, без `authGuard`: документация не требует аккаунта, как и сам факт существования API
- Разделы по эндпоинтам на заглушечной схеме — статичный список из `TECH-SPEC.md` §7.2 (метод, путь, краткое описание), не генерируется из Zod (это 013)
- Аутентификация: пример заголовка `Authorization: Bearer …`
- Лимиты: значения размера файла и квоты — **не задублированы**, взяты из `packages/shared` (`MAX_FILE_SIZE_BYTES`, `USER_STORAGE_QUOTA_BYTES`); остальные лимиты (rate limit, страницы PDF, таймауты) — текстом из `TECH-SPEC.md` §6, этих констант в коде пока нет, вводить их сейчас — не задача 023 (см. «Отвергнутые варианты»)
- Ошибки: таблица кодов, статусов и признака `retryable` — **сгенерирована из `ERROR_CODES`** (`packages/shared`) и текстов `ERROR_MESSAGE_KEYS`/словаря i18n, не переписана вручную
- Пример интеграции: `curl -X POST … -o result.png` для конвертации и `curl … /v1/files` для списка — статичные блоки кода, моноширинный текст
- Ссылка «Документация» в шапке — видна всем, не только вошедшим (публичная страница)

## Не входит

| Что | Где будет |
|---|---|
| Реальная OpenAPI-схема из Zod, интерактивный «Try it» | 013 |
| Значения rate limit/страниц/таймаутов как код-константы в `packages/shared` | Не задача 023 — сейчас их не проверяет ни один эндпоинт (002/003/005/012), заводить константы раньше проверки преждевременно |
| Кнопка «Копировать» на блоках кода | Не в чек-листе 023 (в отличие от 022, где копирование — явное требование к полю ключа) |

## Поведение

- Открывает `/api-docs` без сессии → страница открывается как обычно, редиректа нет.
- Видит: базовый URL и HTTPS-only оговорку, пример заголовка авторизации, список эндпоинтов, лимиты, таблицу кодов ошибок, два примера `curl`.
- Меняет язык/тему → статичный текст переводится, блоки кода (пути/заголовки/JSON-ключи) остаются как есть — это протокол, не UI-текст.
- Из шапки (любое состояние входа) переходит по ссылке «Документация».

## Ошибочные сценарии

Страница полностью статична — сценариев ошибок нет.

## План

### Подход

`features/api-docs/` — один маршрут, один компонент страницы, без стора и без сети (совсем статика, в отличие от 021/022). Данные для разделов «Эндпоинты» и «Ошибки» — не хардкод дважды: список эндпоинтов — локальная константа фичи (это стаб, а не контракт, поэтому не в `packages/shared`), таблица ошибок построена из уже существующих `ERROR_CODES` и `ERROR_MESSAGE_KEYS` — правка кода ошибки в 004/005 автоматически меняет и документацию.

### Открытый вопрос — блока кода нет в `DESIGN.md`

Как и тумблер/скелетон в 021: в `DESIGN.md` нет отдельного компонента «блок кода», только требование «моноширинный». Предлагаю по умолчанию: `bg-canvas`, `border border-hairline`, радиус `lg`, `p-4`, `font-mono text-body-sm`, горизонтальный скролл при переполнении. Не блокирую план этим — если нужно другое, поправим после того, как увидите результат.

### Риски и границы транзакций

БД и сеть не затрагиваются, страница полностью статична. Единственный риск — рассинхрон списка эндпоинтов (локальный стаб) с `TECH-SPEC.md` §7.2, если один поменяют без другого; таблица ошибок от этого риска избавлена изначально (строится из кода).

### Мои тест-кейсы

- Сверить построчно список эндпоинтов страницы с `TECH-SPEC.md` §7.2 — ничего не забыто, ничего не выдумано
- Добавить временно новый код в `ERROR_CODES` (руками, для проверки) — он должен появиться в таблице без правки компонента
- 320px: длинный `curl`-пример скроллится внутри своего блока, не расширяет страницу
- Тёмная тема: код-блок остаётся читаемым, граница видна на `bg-canvas`
