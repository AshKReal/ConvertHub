| Статус | принято владельцем |

## Задача

Зона загрузки на странице конвертации: пользователь перетаскивает файл или выбирает его через диалог и видит, что файл принят. Это центральный элемент продукта — без него страница направления остаётся заглушкой, а контракт запроса к бэкенду не зафиксирован.

## Входит

- Три состояния: `empty` → `dragover` → `selected`, на моках, без единого сетевого запроса
- Счётчик глубины `dragenter` / `dragleave` — переход курсора на дочерний элемент не гасит подсветку
- Выбор файла через диалог: скрытый `input[type=file]` с `accept` по направлению
- На мобильном перетаскивания нет: надпись о нём скрыта, зона работает как крупная кнопка
- Контракт `POST /v1/convert` на клиенте: Zod-схема полей в `packages/shared` и сборка `FormData` без ручного `Content-Type`
- Лимит размера и MIME-типы направлений — в `packages/shared`, не в разметке
- Размер выбранного файла показывается моноширинным с табличными цифрами и локализованными единицами
- Тексты зоны — в словаре i18n на всех трёх языках

## Не входит

| Что | Где будет |
|---|---|
| Состояния `uploading`, `converting`, `done`, `error`, `quotaFull` | 006 |
| Кнопка запуска конвертации в состоянии `selected` | 006 — она запускает автомат, которого ещё нет; мёртвая кнопка хуже её отсутствия |
| Отклонение файла по размеру и типу, тексты ошибок | 004 (коды) и 006 (показ) |
| Реальный запрос, прогресс, отмена | 005 |
| Обрезка длинного имени файла по центру с сохранением расширения | 021, где это правило сформулировано в `DESIGN.md` |

## Поведение

- Когда пользователь открывает `/convert/jpg-to-png`, он видит пунктирную зону с иконкой, приглашением перетащить файл и подписью «JPG до 10 МБ».
- Когда пользователь тащит файл над зоной, фон становится `accent-subtle`, граница — сплошной `accent-hover`, иконка окрашивается, зона увеличивается на 1%.
- Когда курсор с файлом проходит над вложенными элементами зоны, подсветка не мигает.
- Когда пользователь отпускает файл, зона показывает имя файла и его размер моноширинным шрифтом.
- Когда пользователь нажимает «Выбрать другой файл», зона возвращается в исходное состояние.
- Когда пользователь нажимает на пустую зону или на неё приходит фокус и `Enter`, открывается диалог выбора файла.
- Когда пользователь тащит файл, а один уже выбран, зона показывает `dragover`; отмена перетаскивания возвращает ранее выбранный файл, а не пустое состояние.
- Когда ширина экрана меньше `sm`, надпись о перетаскивании заменяется на «Выберите файл».

## Ошибочные сценарии

Отказных путей на этой спеке нет: любой файл принимается в состояние `selected`, проверка типа и размера — 004/006, ответы сервера — 005. Единственная защита — атрибут `accept` в диалоге, он фильтрует, но не гарантирует.

| Ситуация | Что видит пользователь | Код |
|---|---|---|
| Перетащен файл неподходящего типа | Файл выбран; отклонение появится с проверками в 006 | `UNSUPPORTED_FILE_TYPE` (004) |
| Перетащена папка или несколько файлов | Берётся первый файл списка | — |

## Критерии приёмки

- [ ] Перетаскивание файла над зоной подсвечивает её и не мигает при движении курсора внутри
- [ ] Отмена перетаскивания вне зоны возвращает предыдущее состояние, а не `empty`
- [ ] Клик по пустой зоне открывает диалог; `Tab` + `Enter` делают то же
- [ ] Выбранный файл показан именем и размером; «Выбрать другой файл» возвращает в `empty`
- [ ] Высота зоны в состояниях `empty`, `dragover`, `selected` одинакова — страница под курсором не прыгает
- [ ] Обе темы, три языка, ширина 320px
- [ ] Изменение `MAX_FILE_SIZE_BYTES` в `packages/shared` меняет подпись в зоне без правок фронтенда
- [x] `pnpm typecheck` и `pnpm lint` зелёные
- [x] `any` в диффе отсутствует
- [x] Секретов и HEX-цветов в диффе нет (единственный HEX — регулярка валидации `background` в Zod-схеме, это значение от пользователя, не токен)

## План

### Подход

Состояние зоны наружу — дискриминантное объединение `empty | dragover | selected`, как требует `ARCHITECTURE.md` §6.4. Внутри оно вычисляется из двух сигналов: выбранного файла и глубины перетаскивания. Это не набор булевых флагов: невозможных комбинаций нет, а `dragover` поверх уже выбранного файла корректно откатывается к `selected` — при хранении одного мутируемого объединения предыдущий файл пришлось бы дублировать отдельным полем.

Контракт `POST /v1/convert` фиксируется здесь и целиком: Zod-схема полей (`target`, `save`, `quality`, `background`, `dpi`) в `packages/shared/src/schemas/convert.ts` и функция сборки `FormData` в фиче. Сам HTTP-вызов не пишется — он появится в 005 и по `ARCHITECTURE.md` §6.3 уже описан; писать сейчас метод, который никто не вызывает, значит оставить мёртвый код на две стадии. `Content-Type` не выставляется нигде: браузер проставит `multipart/form-data` с boundary сам.

Реестр направлений переезжает в `packages/shared/src/constants/formats.ts` и обрастает MIME-типами и целевым форматом — имя и содержимое файла заданы `ARCHITECTURE.md` §3. Лимит размера — `constants/limits.ts`, оттуда же его берёт подпись под зоной: проверочное свойство общего пакета из `ARCHITECTURE.md` («поменяли 10 МБ на 8 МБ — фронт перестал компилироваться там, где значение захардкожено») выполняется буквально.

Размер файла форматируется через `Intl.NumberFormat` со `style: 'unit'`: единицы («МБ» / «MB») приходят из локали, а не из словаря. Пайп `shared/pipes` для этого не подходит — ему пришлось бы инжектить локаль из `core`, что запрещено направлением зависимостей.

Одинаковая высота состояний достигается одинаковой структурой (иконка → заголовок → строка подписи), а не фиксированным значением: числа высоты зоны в `DESIGN.md` нет, а изобретать его правила запрещают.

### Отвергнутые варианты

| Вариант | Почему отвергнут | Когда вернёмся |
|---|---|---|
| Хранить состояние одним сигналом-объединением | `dragover` затирает выбранный файл, приходится дублировать его вторым полем — те же данные в двух местах | Никогда |
| Булевы флаги `isDragover` / `hasFile` | Четыре комбинации, из которых валидны три; компилятор не помогает (`ARCHITECTURE.md` §6.4) | Никогда |
| Написать `convert.api.ts` с реальным `http.post` уже сейчас | Мёртвый код до 005; форма вызова уже зафиксирована в `ARCHITECTURE.md` §6.3 | 005 |
| Слушать `dragenter`/`dragleave` без счётчика, гасить по `relatedTarget` | Работает не во всех браузерах при вложенных элементах и ломается на быстрых движениях | Никогда |
| Отдельная разметка зоны для мобильного | Два шаблона расходятся при первой же правке; хватает скрытия одной надписи по брейкпоинту | Никогда |
| Фиксированная высота зоны числом | Значения нет в `DESIGN.md`, а подбирать самому запрещено | Когда владелец назовёт число |
| Пайп `formatBytes` в `shared/pipes` | Локализованные единицы требуют доступа к локали, `shared → core` запрещено | Если появится потребность в форматировании без локали |

### Риски и границы транзакций

БД не затрагивается. Риски:

- Переименование `conversion-directions.ts` → `formats.ts` трогает четыре импорта в уже принятом коде 024/027. Сборка ловит промах сразу, но дифф выходит за границы «только зона загрузки».
- `Intl.NumberFormat` со `style: 'unit'` требует типов `es2020.intl`; при понижении `target` в `tsconfig` формат отвалится на типах, а не в рантайме.
- Событие `drop` без `preventDefault` на `dragover` браузер обрабатывает сам — открывает файл в соседней вкладке. Проверяется руками, тестом на этой стадии не покрыто.
- `accept` в диалоге не гарантирует тип: пользователь выберет «Все файлы». Реальная проверка — по magic bytes на сервере (002).

### Мои тест-кейсы

- Перетащить файл, провести курсором по иконке и тексту внутри зоны — подсветка не мигает ни разу
- Начать перетаскивание и увести курсор за пределы окна — зона вернулась в прежнее состояние
- Выбрать файл, затем перетащить другой — заменился, старый не остался
- Перетащить сразу три файла — взят первый, ошибок в консоли нет
- Перетащить папку — приложение не падает
- Бросить файл мимо зоны, в тело страницы — браузер не открыл его вместо приложения
- Файл с именем в 120 символов — вёрстка зоны не разъезжается
- Файл размером 0 байт и 9,9 МБ — размер читается, цифры не пляшут
- `Tab` до зоны, `Enter` — открылся диалог; `Esc` в диалоге — состояние не изменилось
- Ширина 320px — надписи о перетаскивании нет, зона нажимается пальцем
