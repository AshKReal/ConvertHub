## Задача

Вошедший пользователь должен видеть свои сохранённые файлы: сколько их, сколько места они занимают, и управлять тем, что хранится дальше. Без этого экрана «Сохранить» на зоне загрузки (006) ведёт в никуда, а квота (010) нечем показать до бэкенда.

## Входит

- Экран `/files` (только для вошедшего — тот же `authGuard`, что у `/profile`, 020): список файлов на моковом массиве
- Курсорная пагинация на клиенте поверх мокового массива: кнопка «Показать ещё» подгружает следующую порцию, скрывается, когда данные кончились
- Переключатель `save` на каждой строке — локальное состояние, без запроса
- Индикатор занятого места (`shared/ui/storage-quota`) — лимит из `USER_STORAGE_QUOTA_BYTES` (`packages/shared`), занято — сумма размеров файлов с `save = true` в мок-списке (пересчитывается живьём при переключении тумблера)
- Пустое состояние (список пуст)
- Состояние первой загрузки — скелетоны строк вместо списка
- Ссылка «Мои файлы» в шапке для вошедшего (по аналогии с `/profile` из 020 — то же правило 025: «пункты навигации добавляются вместе с экранами, которым есть куда вести»)

## Не входит

| Что | Где будет |
|---|---|
| Реальный `GET /v1/files`, реальная БД-пагинация (`WHERE id < :cursor`) | 010 |
| Реальный расчёт `storage_used_bytes`, автоснятие `save` при заполненной квоте с предупреждением | 010 |
| Скачивание файла, удаление файла | Не заявлено в чек-листе 021; скачивание — реальный `GET /v1/files/{id}/download` появляется только в 003, мокать нечем |
| Смешение `files` и `conversions` в одном списке, статус «Ошибка» у строки файла | Осознанно исключено — `TECH-SPEC.md` §10 прямо называет это ошибкой проектирования: у неуспешной конвертации нет файла, значит нет размера и кнопки скачивания |
| TanStack Query | Подключается вместе с этим же списком, но в 010, не здесь (`ARCHITECTURE.md` §6.2) — до тех пор источник данных мок, кешировать нечего |

## Поведение

- Вошедший открывает `/files` → на месте списка несколько строк-скелетонов, через короткую паузу (мок-задержка) они сменяются реальными строками.
- Каждая строка: иконка типа файла, имя (обрезка по центру, расширение видно), размер и дата, бейдж состояния хранения, переключатель `save`.
- Строк больше, чем помещается на первую порцию → под списком кнопка «Показать ещё».
- Нажатие «Показать ещё» → кнопка показывает состояние загрузки, затем к списку добавляется следующая порция; когда моковый массив исчерпан, кнопка исчезает.
- Переключение `save` на строке с `true` на `false` → бейдж меняется на «Временный», индикатор занятого места уменьшается на размер этого файла.
- Переключение обратно на `true` → бейдж «Сохранён», индикатор занятого места растёт обратно.
- Мок-массив пуст (см. «Мои тест-кейсы» — включается вручную для приёмки) → вместо списка и индикатора квоты — пустое состояние с поясняющим текстом.
- Неавторизованный пытается открыть `/files` → редирект на `/login`, как и `/profile` (020).
- В шапке для вошедшего появляется ссылка «Мои файлы» рядом с профилем.

## Ошибочные сценарии

Экран не обращается к сети — ошибок в смысле кодов 004 здесь нет, есть только два состояния данных.

| Ситуация | Что видит пользователь | Код |
|---|---|---|
| Список пуст | Пустое состояние вместо строк и индикатора квоты | — |
| Идёт первая загрузка | Скелетоны вместо строк | — |
| `/files` без сессии | Редирект на `/login`, экран не показывается | — |

## План

### Подход

`features/files/` по структуре `ARCHITECTURE.md` §6.1: `files.routes.ts`, `pages/files-page/`, `components/`, `data/`, `model/`. Стор — `FilesStore` с сигналами `entries`/`loading`/`loadingMore`/`hasMore` и `computed usedBytes` (сумма размеров файлов с `saved = true`), провайдится на самой странице (`providers: [FilesStore]`), а не в `root` — уходишь со страницы, состояние умирает вместе с ней (`ARCHITECTURE.md` §6.1). Мок-данные и искусственная задержка — `data/files.mock.ts`, тем же приёмом, что `MOCK_LOGIN_SUCCEEDS` в 019: константа `MOCK_FILES`, которую можно обнулить руками для проверки пустого состояния.

`/files` защищён тем же `authGuard`, что и `/profile` (020) — личный список файлов гостю показывать нечего, симметрично уже принятому решению.

Категория иконки по типу файла — три категории, что и в 024 (изображение / документ / документ со строками): `png`/`jpg` → изображение, `docx` → документ, `pdf` → документ со строками. Сопоставление `ConversionTarget → category` — в `model/file-entry.ts` (знает о `packages/shared`), сама иконка — `shared/ui/file-type-icon` (принимает уже готовую категорию, не знает про `ConversionTarget`, копируется в другой проект).

Бейдж статуса — **не** «Completed/Failed»: `TECH-SPEC.md` §10 прямо предупреждает, что слияние `files` и `conversions` в интерфейсе даёт строке-ошибке размер и кнопку скачивания, которых у неё быть не может. Здесь список — чисто `files`, бейдж отражает состояние хранения: `saved = true` → «Сохранён» (`success`), `saved = false` → «Временный» (нейтральная пара `text-secondary`/`surface-muted`, не `warning` — предупреждение из §11 относится к принудительному снятию `save` при заполненной квоте, это 010, здесь пользователь сам выключил тумблер).

### Отвергнутые варианты

| Вариант | Почему отвергнут | Когда вернёмся |
|---|---|---|

| `FilesStore` в `providedIn: 'root'` | `ARCHITECTURE.md` §6.1 явно требует провайдить стор на уровне маршрута, не глобально | — |

| `shared/ui/file-type-icon` знает про `ConversionTarget` | Нарушает критерий `shared/ui`: не должен знать доменные типы, должен собираться, если скопировать в другой проект | — |

### Риски и границы транзакций

БД и сеть не затрагиваются. `usedBytes` считается на клиенте из мокового списка — при подключении 010 этот `computed` полностью заменяется на значение с сервера (`users.storage_used_bytes`), пересчёт на клиенте по `save`-тумблеру исчезает вместе с мок-стором.

### Мои тест-кейсы

- `MOCK_FILES = []` (временно, руками) — пустое состояние вместо списка и индикатора квоты, без падения на `usedBytes` от пустого массива
- Обнулить квоту (`USER_STORAGE_QUOTA_BYTES` временно уменьшить) — полоса показывает `danger` при переполнении, `warning` в диапазоне 80–100 %
- Быстро переключить `save` туда-обратно на одной строке несколько раз подряд — индикатор не рассинхронизируется с суммой видимых `saved = true`
- Имя файла длиннее контейнера на 320px — обрезка по центру не съедает расширение
- Клик «Показать ещё», когда до конца мокового массива остаётся меньше полной порции — последняя порция короче остальных, кнопка корректно исчезает после неё
- Тёмная тема: бейдж «Временный» (нейтральная пара) остаётся читаемым, не сливается с фоном строки
