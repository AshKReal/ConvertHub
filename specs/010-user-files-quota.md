## Задача

Экран `/files` (021) принят владельцем на моке — список, пагинация и индикатор квоты рисовались по локальному
массиву. Без этой спеки «Сохранить» на зоне загрузки не ведёт никуда (конвертация всегда безвозвратно временная),
а квота, о которой всюду говорит документация, нигде по-настоящему не считается.

## Входит

- Курсорная пагинация в БД (`WHERE id < :cursor ORDER BY id DESC`, ULID) — `GET /v1/files`
- Тумблер `save` на уже сохранённом файле — `PATCH /v1/files/:id`
- Реальный расчёт `storage_used_bytes`, автоснятие `save` при заполненной квоте на конвертации с предупреждением
- TanStack Query (первое подключение в проекте) — список файлов + квота (`['me']`), инвалидация вместе после мутаций
- Подключение 021 к реальным данным вместо мока
- Авто-`save` для вошедшего при конвертации (решение владельца — см. «Решено с владельцем» ниже; в исходном UI
  не было и не подразумевалось отдельного чекбокса)

## Не входит

| Что | Где будет |
|---|---|
| Кнопки «Скачать»/«Удалить» на строке файла | Не заявлено ни в 021, ни в чек-листе 010 — `GET /v1/files/{id}/download` (003) остаётся не выведенным на эту страницу |
| Testcontainers/полная атомарность quota-check при параллельных конвертациях одного пользователя | Пред-чтение `storageUsedBytes` вне транзакции — тот же класс гонки, что уже принят у in-memory rate/concurrency лимитеров (007/005), не 🔒-инвариант |
| TanStack Query для профиля (020) | Профиль остаётся на `AuthService.user` — `['me']` заводится только под квоту/файлы/dropzone |

## Решено с владельцем в этой сессии (`AskUserQuestion`, два вопроса)

1. **Снятие `save` с уже сохранённого файла — мягкое истечение**, тот же механизм, что у гостевых файлов
   (`File.expiresAt`), не немедленное физическое удаление. Обратимо, пока `expiresAt` не наступил.
2. **Авто-`save` для вошедшего, без чекбокса на зоне загрузки.** По ходу реализации обнаружился реальный разрыв:
   в UI никогда не было чекбокса «сохранить» (ни в одном мок-состоянии 006/019, ни в момент начала этой спеки) —
   реальный запрос конвертации всегда слал `save: undefined`, и без него 010 закрывался бы кодом, непроверяемым
   через UI в принципе (список/квота/тумблер были бы готовы и проверены только curl'ом). Текст
   `dropzone.quotaFull.title` («файл сконвертируется, но не сохранится») уже намекал на модель «сохраняем по
   умолчанию» — подтверждено владельцем: вошедший сохраняет автоматически, `/files` — способ отказаться
   постфактум (уже готовый тумблер).

## Поведение

- Вошедший конвертирует файл → сохраняется автоматически (квота позволяет) → виден на `/files` сразу после.
- Квота заполнена → конвертация всё равно успешна, файл не сохраняется, тост с объяснением.
- Тумблер `save` на строке `/files` → квота освобождается/восстанавливается мгновенно, обратимо туда-обратно.
- Явное включение `save` обратно, когда квота уже не позволяет → ошибка, файл остаётся временным.
- Гость на зоне загрузки квоты не имеет — файл никогда не сохраняется, состояние `quotaFull` не наступает.
- Вошедший с заполненной квотой видит зону загрузки в состоянии `quotaFull` ещё до выбора файла.

## Ошибочные сценарии

| Ситуация | Что видит пользователь | Код |
|---|---|---|
| Конвертация с `save` по умолчанию при заполненной квоте | Файл сконвертирован, не сохранён, тост | — (заголовок `X-Save-Skipped-Reason`, не JSON-код — тело ответа бинарное) |
| Явное `PATCH .../{save:true}` при заполненной квоте | Ошибка, файл остаётся временным | `STORAGE_QUOTA_EXCEEDED` (422) |
| `PATCH` на чужом/несуществующем/истёкшем файле | Не раскрывает разницу | `FILE_NOT_FOUND` (404) |
| `GET`/`PATCH /v1/files/*` без сессии | — | `UNAUTHENTICATED` (401) |

## План

Полный план с обоснованиями — в истории сессии; здесь — выжимка реализованного.

### Подход

`File.expiresAt` (003) уже делает то, что нужно снятию `save` — миграция не понадобилась. Курсорный индекс
(`idx_files_user_cursor`) был заложен в 003 заранее под эту спеку. `FilesService.saveConversionResult` возвращает
дискриминантное объединение (`ARCHITECTURE.md` — тот же принцип, что состояние зоны загрузки), не
`SavedFile | null`: вызывающему нужно различать «не сохранили из-за квоты» (успех, предупреждение) от «сохранить
не удалось» (тоже успех клиенту, тихий сбой). `GET /v1/auth/me` расширен `storageUsedBytes` через отдельную
`meResponseSchema` (не общий `authUserSchema`) — `login`/`register`/`refresh` не обязаны знать квоту на момент
входа, `/me` — намеренно живой повторный запрос.

TanStack Query — первое подключение в проекте (`ARCHITECTURE.md` §6.2: «вместе с первым серверным списком»).
`['me']` — общий ресурс `core/services/me.ts`, читается и `/files` (полоса квоты), и `dropzone` (`quotaFull` до
выбора файла) — `features → features` запрещено, общий потребитель только `core`.

### Отвергнутые/скорректированные варианты

| Вариант | Почему отвергнут |
|---|---|
| Немедленное физическое удаление при снятии `save` | Решение владельца — мягкое истечение, тот же механизм, что у гостя |
| Чекбокс «сохранить» на зоне загрузки | Решение владельца — авто-save для вошедшего, чекбокса не было и не планировалось |
| Расширение `authUserSchema` целиком под `storageUsedBytes` | Отдельная `meResponseSchema` — `login`/`register`/`refresh` не должны тянуть лишний select ради снэпшота, который тут же устареет |
| Блокировать конвертацию при заполненной квоте | Не заявлено — квота ограничивает только *сохранение*, не саму конвертацию (TECH-SPEC.md) |

### Побочные находки (не входили в план, найдены и исправлены по ходу)

- **`originalFilename` никогда не передавался** от `ConversionController` в `FilesService.saveConversionResult` —
  каждый сохранённый файл получал `null` молча. Исправлено: `file.originalname` (Multer) теперь идёт через
  `ConversionService.convert` до сохранения.
- **`exposedHeaders` отсутствовал в CORS** (`main.ts`) — `X-File-Id` (003) и новый `X-Save-Skipped-Reason` были
  нечитаемы из браузера с самого начала (cross-origin, apps/web ≠ apps/api), просто до тоста 010 никто не
  пытался прочитать заголовок ответа `/v1/convert` из JS. Найдено ручной браузерной проверкой, не тайпчеком.

### Риски

Пред-чтение `storageUsedBytes` вне транзакции (и на конвертации, и в `updateSaveFlag`) — тот же класс гонки, что
уже принят у in-memory rate/concurrency лимитеров: параллельные операции одного пользователя теоретически могут
провести квоту на волосок выше лимита. Не 🔒-инвариант, осознанно не устраняется в этом проходе.
