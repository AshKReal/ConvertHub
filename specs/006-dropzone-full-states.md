## Задача

Пользователь должен пройти весь путь конвертации — от выбора файла до результата или отказа — не выходя из зоны загрузки, и на каждом шаге видеть, что именно происходит. Зона загрузки сейчас понимает только три состояния из восьми и не умеет запускать конвертацию: кнопка запуска была сознательно отложена сюда спекой 001.

## Входит

- Полный конечный автомат зоны загрузки: `empty → dragover → selected → uploading → converting → done`, с выходом в `error` из любого шага, плюс `quotaFull` до выбора файла — все восемь состояний `DESIGN.md`, раздел «Зона загрузки»
- Кнопка запуска в `selected`, включающая мок-загрузку и мок-конвертацию на `setTimeout`/`setInterval`, без реального запроса
- Отмена в `uploading` (просто возврат в `empty`); в `converting` отмены нет
- Клиентская проверка `FILE_TOO_LARGE` (единственный код, который зона может проверить сама, без бэкенда) — сразу в `error`, минуя `selected`
- `ToastService` (`core/services`) и презентационный `shared/ui/toast` — для категории «rate limit, таймаут, сбой конвертера» из `ARCHITECTURE.md` §8, которую зона не показывает у себя
- `USER_STORAGE_QUOTA_BYTES` в `packages/shared` — предел, который уже назван в `AGENTS.md`, но нигде не был константой

## Не входит

| Что | Где будет |
|---|---|
| Реальный `POST /v1/convert`, реальный прогресс, реальная отмена (обрыв HTTP) | 005 |
| Реальный расчёт занятого места, автоснятие `save` при заполненной квоте | 010 |
| Проверка остальных кодов файла (`UNSUPPORTED_FILE_TYPE`, `FILE_CORRUPTED`, `IMAGE_TOO_LARGE`, `TOO_MANY_PAGES` и т.д.) — они требуют чтения содержимого файла (magic bytes, пиксели, страницы), это работа бэкенда | 002, 005 |
| Баннer для категории «сервис недоступен» | появится вместе с первым источником такой ошибки — не раньше 026 |
| Инлайн-ошибки под полем формы | 019, там впервые появляются поля форм |
| Ссылка «управление файлами» в тексте `quotaFull` — ведёт на страницу, которой ещё нет | 021 |

## Поведение

- Файл больше 10 МБ выбран (пикером или drag-drop) → зона переходит сразу в `error`, `selected` не показывается.
- В `selected` нажата кнопка «Конвертировать» → `uploading` с полосой прогресса 0–100%, кнопкой отмены.
- Прогресс достиг 100% → `converting`: неопределённый индикатор, кнопка отмены скрыта.
- Мок-конвертация завершилась успехом (по умолчанию) → `done`: галочка, имя и размер, кнопка скачивания.
- Мок-конвертация завершилась отказом (флаг `MOCK_FORCE_CONVERSION_ERROR`, до 026 переключается только руками) → зона возвращается в `selected`, тост с `CONVERSION_FAILED` снизу справа, не исчезает автоматически дольше пяти секунд лишь потому, что это ошибка — по `DESIGN.md` ошибки вообще не скрываются сами.
- Квота исчерпана (флаг `MOCK_STORAGE_USED_BYTES`, до 010 переключается только руками) → зона до выбора файла показывает `quotaFull` вместо `empty`; выбор файла всё равно работает и ведёт в обычный `selected`.
- В `error` нажата «Попробовать снова» → полный сброс в `empty`, а не возврат к тому же файлу.

## Ошибочные сценарии

| Ситуация | Что видит пользователь | Код |
|---|---|---|
| Файл больше лимита | «File is {actual}, the limit is {max}. Choose a smaller file.» в зоне | `FILE_TOO_LARGE` |
| Мок-сбой конвертации | Тост «Conversion failed unexpectedly...», зона возвращается в `selected` | `CONVERSION_FAILED` |

## Критерии приёмки

- [ ] Файл 11 МБ → зона сразу в `error`, текст содержит оба размера в МБ, кнопка «Попробовать снова» возвращает в `empty`
- [ ] Файл ≤10 МБ → «Конвертировать» → прогресс 0→100% → «Конвертируем» без процентов → «Готово» с кнопкой скачивания; кнопки отмены нет в `converting`, есть в `uploading`
- [ ] `MOCK_FORCE_CONVERSION_ERROR = true` → тост снизу справа с текстом `CONVERSION_FAILED`, зона возвращается в `selected`, тост не закрывается сам
- [ ] `MOCK_STORAGE_USED_BYTES = USER_STORAGE_QUOTA_BYTES` → зона до выбора файла показывает предупреждение вместо приглашения, выбор файла всё равно работает
- [ ] Обе темы: `bg-surface`/`border-*` каждого состояния совпадают с токенами `.dark` (проверено вычисленными стилями, не только на глаз — CSS-переход 150 мс)
- [ ] 320px: текст ошибки на русском не переполняет зону
- [ ] `pnpm typecheck` и `pnpm lint` зелёные
- [ ] `any` в диффе отсутствует
- [ ] Секретов и HEX-цветов в диффе нет

## План

### Подход

Автомат живёт в `Dropzone` как и раньше — четыре сигнала (`file`, `phase`, `progress`, `error`) вместо одного, `computed` собирает их в `DropzoneState`. `phase` — свой маленький union (`idle | uploading | converting | done`), не пересекается с `DropzoneState['kind']` напрямую: `file === null` уже отличает «файла нет» от «файл есть», `phase` отличает шаги внутри «файл есть». Мок-прогресс — `setInterval` с шагом раз в 150 мс, мок-конвертация — один `setTimeout` на 900 мс.

Категории ошибок из `ARCHITECTURE.md` §8 ведут в разные места: «файл отклонён» (пока это только `FILE_TOO_LARGE`, посчитанный на клиенте) — в зону; «сбой конвертера» — в тост. Это разделение проведено по самой таблице, не изобретено заново.

Квота — булев флаг, вычисленный один раз при создании компонента из двух захардкоженных чисел (`MOCK_STORAGE_USED_BYTES` сравнивается с `USER_STORAGE_QUOTA_BYTES`), а не сигнал: спека 010 заменит это на реальный запрос `['me']`, здесь достаточно константы, которую владелец подвигает руками для приёмки.

Кнопка «Скачать» в `done` реально скачивает — берёт байты уже выбранного `File` через `URL.createObjectURL` и подставляет имя результата. Это не имитация клика в пустоту: настоящий файл (изменённые байты) отдаст 003/005, но сам факт «скачивание работает» проверяем уже сейчас, без выдуманного сетевого вызова.

### Отвергнутые варианты

| Вариант | Почему отвергнут | Когда вернёмся |
|---|---|---|
| Мок-исход конвертации по имени файла (например, `fail.jpg` → ошибка) | Скрытая магия, которую владелец не найдёт без чтения кода; хардкоженный флаг рядом с `MOCK_STORAGE_USED_BYTES` — тот же уровень мока, но виден в одном месте и одним стилем | — |
| Зона сама показывает все категории ошибок, включая «сбой конвертера» и «сервис недоступен», без тоста/баннера | Прямо противоречит таблице `ARCHITECTURE.md` §8: там эти категории явно разведены по местам показа | — |
| `quotaFull` как булев оверлей поверх любого состояния (баннер над зоной, а не отдельный `kind`) | `ARCHITECTURE.md` §6.4 называет его «восьмым состоянием» дискриминантного объединения, не отдельным слоем; менять контракт без причины — не туда | Если 010 покажет, что баннер поверх всех состояний нужнее одного `kind` до выбора файла |
| Кнопка «Скачать» — заглушка без реального клика (просто визуальный элемент) | Мёртвая кнопка на ручной приёмке выглядит как баг, а не как «ещё не подключено»; переиспользовать байты уже выбранного файла — три строки, не отдельная фича | — |

### Риски и границы транзакций

БД не затрагивается, всё в памяти компонента. Единственный риск — рассинхрон моков с будущим бэкендом: `MOCK_FORCE_CONVERSION_ERROR` всегда бьёт в `CONVERSION_FAILED`, хотя реальный бэкенд может вернуть любой retryable-код из реестра; когда 005/026 подключат реальный ответ, вызов `toast.show()` переедет туда без изменения сигнатуры `ToastService`.

Таймеры (`setInterval`/`setTimeout`) обязаны останавливаться при `clear()` — иначе быстрый «выбрать другой файл» посреди аплоада оставляет висящий таймер, который позже допишет прогресс в уже очищенное состояние. Проверено `stopTimers()` на каждом выходе из автомата.

### Мои тест-кейсы

- Файл ровно 10 485 760 байт (граница) → не ошибка, `10 485 761` → ошибка с обоими числами.
- Клик «Отмена» на 40% прогресса → зона мгновенно `empty`, повторный выбор того же файла работает.
- Двойной клик «Конвертировать» (гонка) → второй вызов `start()` не запускает второй интервал: guard проверяет `phase() === 'idle'`, а не только `file() !== null` (без этого второго условия вызов посреди `uploading` создавал бы висящий второй `setInterval`).
- Drag-and-drop нового файла поверх `done`/`uploading` — не подменяет текущий (только явные `empty`/`dragover`/`quotaFull` принимают `select()`).
- `MOCK_STORAGE_USED_BYTES` выставлен, но пользователь так и не выбрал файл — `quotaFull` остаётся, `dragover` всё равно подсвечивается при наведении файла.
- Обе темы, RU/UK тексты на 320px — переполнения нет (проверено скриншотами).
