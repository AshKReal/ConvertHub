## Задача

Пользователь, забывший пароль, должен иметь способ его восстановить, а вошедший — управлять паролем и удалить аккаунт. Всё на моках: без этих экранов подключать реальное восстановление (009) и профиль будет некуда — сначала форма и состояния, потом сеть.

## Входит

- Экран «Забыли пароль» (`/forgot-password`): форма email → состояние «проверьте почту», один и тот же результат независимо от того, существует ли адрес (`TECH-SPEC.md` §8.5) — мок соблюдает инвариант с самого начала, чтобы бэкенду (009) не пришлось менять UX
- Экран сброса пароля по токену (`/reset-password/:token`): новый пароль + подтверждение, токен из URL — заглушка, не проверяется
- Ссылка «Забыли пароль?» на экране входа (019), ведущая на `/forgot-password`
- Профиль (`/profile`, только для вошедшего): смена пароля (форма + сабмит-заглушка, завершает мок-сессию и уведомляет — `AUTH-RULES.md` §2 «ВСЕГДА при смене пароля инвалидировать все сессии и уведомлять»), список привязанных провайдеров входа (мок), удаление аккаунта через модалку подтверждения
- `core/guards/auth-guard.ts` — первый маршрут, которому есть смысл защищать (019 сознательно отложил guard до этого момента)
- `shared/ui/confirm-dialog` — переиспользуемая модалка подтверждения поверх уже существующего `ModalService`/`NgComponentOutlet` в `Layout` (заведён в 025, потребителей ещё не было); пригодится 022 для отзыва/перевыпуска ключа
- Ссылка на `/profile` из шапки (email/аватар кликабельны), когда пользователь вошёл

## Не входит

| Что | Где будет |
|---|---|
| Реальные `POST /auth/forgot-password`, `/auth/reset-password`, генерация и проверка токена | 009 |
| Реальная смена пароля, инвалидация сессий, письмо-уведомление | 009 |
| Реальное удаление аккаунта | 009 |
| Реальный список привязанных провайдеров (таблица `identities`, несколько провайдеров на аккаунт одновременно) | 008/009; здесь список выводится из мок-сессии (один провайдер — тот, которым вошли) |
| Отвязка провайдера, запрет отвязки последнего способа входа | не в чек-листе 020; отдельная спека, когда появится реальный список |
| `guestGuard`, закрывающий `/login`/`/register` от уже вошедшего | нет заявленной проблемы, добавится, когда появится |
| Rate limit на форму восстановления | сеть отсутствует, лимитировать нечего до 009 |

## Поведение

- Открывает `/forgot-password` → форма с полем email и кнопкой отправки.
- Отправляет пустое поле → «Введите email» под полем, экран не переключается.
- Отправляет некорректный формат → «Введите корректный email» под полем.
- Отправляет валидный email (любой, мок не проверяет существование) → экран сменяется на «Проверьте почту», с тем же текстом независимо от адреса.
- Открывает `/reset-password/:token` с любым значением токена в адресе → форма нового пароля.
- Отправляет пароль короче 8 символов → текст ошибки под полем, сабмит не проходит.
- Пароли в полях «новый» и «подтверждение» не совпадают → «Пароли не совпадают» под полем подтверждения.
- Отправляет валидную пару → сообщение об успехе и ссылка на `/login`.
- Открывает `/profile`, не будучи вошедшим → редирект на `/login`.
- Вошедший открывает `/profile` → видит email, форму смены пароля, список провайдеров (использованный при входе — «подключён», остальные два — «не подключён»), кнопку «Удалить аккаунт».
- Отправляет форму смены пароля с валидными полями → тост «Пароль изменён, войдите заново», сессия сбрасывается (как «Выйти»), редирект на `/login`; запрос никуда не уходит.
- Нажимает «Удалить аккаунт» → модалка с предупреждением о необратимости, кнопки «Отмена»/«Удалить».
- Подтверждает удаление → сессия сбрасывается (как «Выйти» в шапке), редирект на `/`.
- Отменяет (кнопка «Отмена», клик по фону или `Escape`) → модалка закрывается, состояние не меняется.
- Кликает по email/аватару в шапке → переход на `/profile`.

## Ошибочные сценарии

Экраны не обращаются к сети — все ошибки клиентские, валидационные.

| Ситуация | Что видит пользователь | Код |
|---|---|---|
| Пустой email на «Забыли пароль» | «Введите email» под полем | — |
| Некорректный формат email | «Введите корректный email» под полем | — |
| Пустой/короткий пароль при сбросе или смене | «Пароль должен быть не короче 8 символов» / «Введите пароль» под полем | — |
| Пароли не совпадают (сброс) | «Пароли не совпадают» под полем подтверждения | — |
| Пустой текущий пароль при смене в профиле | «Введите текущий пароль» под полем | — |
| `/profile` без сессии | Редирект на `/login`, экран не показывается | — |
| `/reset-password` без сегмента токена | Маршрут не совпадает → срабатывает `**` → редирект на `/` (как для неизвестного направления в 024) | — |

## Критерии приёмки

- [ ] `/forgot-password` с пустой формой → ошибка под полем, экран не переключается
- [ ] `/forgot-password` с валидным email (в том числе заведомо не существующим) → одинаковый экран «Проверьте почту»
- [ ] `/reset-password/anything123` с паролем короче 8 символов → ошибка под полем
- [ ] `/reset-password/anything123` с несовпадающими паролями → «Пароли не совпадают»
- [ ] `/reset-password/anything123` с валидной парой → экран успеха со ссылкой на `/login`
- [ ] `/profile` без входа → редирект на `/login`
- [ ] `/profile` после входа → email, список из трёх провайдеров с ровно одним «подключён»
- [ ] Смена пароля в профиле с валидными полями → тост «Пароль изменён, войдите заново», выход из сессии, редирект на `/login`
- [ ] «Удалить аккаунт» → модалка → подтверждение → выход из сессии, редирект на `/`, шапка возвращается к «Войти»
- [ ] Модалка закрывается по «Отмена», клику по фону и `Escape`, без побочных эффектов
- [ ] Email/аватар в шапке ведут на `/profile`
- [ ] Обе темы, три языка, 320px — формы и модалка не переполняются
- [ ] `pnpm typecheck` и `pnpm lint` зелёные
- [ ] `any` в диффе отсутствует
- [ ] HEX-цветов в диффе нет

## План

### Подход

Три новых экрана и один переиспользуемый примитив, всё поверх инфраструктуры 019/025:

- **`/forgot-password`, `/reset-password/:token`** — новые страницы в уже существующей `features/auth/`, тем же паттерном, что `login-page`/`register-page`: `Reactive Forms`, локальный `signal` для переключения под-состояния экрана (`form` ↔ `sent` на «Забыли пароль», аналогично `showError` в `login-page`).
- **`/profile`** — новая фича `features/profile/` (не `features/auth/`: `ARCHITECTURE.md` §6.1 явно перечисляет `profile` отдельной веткой от `auth`, и `features → features` запрещено, так что общее между ними — только через `shared`/`core`).
- **`core/guards/auth-guard.ts`** — `CanActivateFn`, читает `AuthService.user()`, при `null` — `router.navigateByUrl('/login')` и `false`; без `returnUrl` (не запрошено чек-листом, добавлять нечего).
- **`shared/ui/confirm-dialog`** — дженерик-компонент (`title`/`message`/`confirmLabel`/`cancelLabel`/`variant` через `input()`, `confirmed`/`cancelled` через `output()`), не знает про удаление аккаунта — используется как контент `ModalService.open()`. Стили — уже определённые токены `shadow-modal`/`radius-xl`/`surface` (`DESIGN.md`, разделы Elevation, Shapes), выделенного описания «Модалка» в разделе Components нет — если владелец хочет точные отступы/ширину как отдельную запись в `DESIGN.md`, это отдельный вопрos, не блокирующий: используются те же отступы, что и в карточке формата.
- **Клик по фону/`Escape` закрывают модалку** — сейчас у `Layout` есть только сам стек (`ModalService.stack`), backdrop ничего не обрабатывает, потому что до этой спеки у `ModalService` не было ни одного потребителя. Обработчики добавляются в `layout.ts`/`layout.html` рядом с существующим `@for` по стеку — это инфраструктура модалок, а не что-то специфичное для 020.
- **Провайдер в мок-сессии** — `MockUser` получает поле `provider: 'password' | 'google' | 'telegram'`, `AuthService.login()` принимает второй параметр. `oauth-buttons` уже эмитит `OauthProvider` (019), `login-page`/`register-page` сейчас его игнорируют (`onOauth()` без аргумента) — прокидывается дальше.
- **`MIN_PASSWORD_LENGTH`** — сейчас захардкожен отдельно в `register-page.ts` с комментарием, что политика не зафиксирована (`AUTH-RULES.md` §5). Reset-password и смена пароля в профиле — ещё два места с тем же числом; `features → features` нельзя, поэтому константа переезжает в `shared/constants/password-policy.ts` (не `packages/shared` — это не Zod-схема и не серверный контракт, чисто фронтовая мок-подсказка).

| Смена пароля в профиле оставляет пользователя вошедшим, только тост | `AUTH-RULES.md` §2: «ВСЕГДА при смене или сбросе пароля инвалидировать все активные сессии и уведомлять» — мок повторяет реальный инвариант заранее, тем же приёмом, что 019 (единое сообщение об ошибке) и этот черновик (одинаковый ответ на восстановление) | — |
| Отвязка провайдера в профиле | Чек-лист 020 просит только список, не действие; реального списка (`identities`) пока нет — отвязывать нечего | Вместе с 008/009, когда список станет настоящим |

### Риски и границы транзакций

БД и сеть не затрагиваются. Два мок-ограничения стоит держать в голове при приёмке, чтобы не завести их как баги:

- Сессия — сигнал в памяти (019), не переживает обновление страницы. Открыл `/profile`, обновил вкладку — вылетел на `/login`. Это ограничение мок-стадии, не регрессия; переживёт обновление только с реальными cookie в 007.
- Список провайдеров в профиле — не настоящая связка аккаунтов, а проекция одного поля `provider` из мок-сессии. Когда 008/009 подключат таблицу `identities`, весь блок профиля с провайдерами придётся переписать на реальные данные (возможно, несколько одновременно привязанных), а не расширять этот мок.

### Мои тест-кейсы

- `/reset-password/` без токена в адресе (обрезанный URL) — не путать 404 с «просто нет такого маршрута»: должен сработать `**`, редирект на `/`
- Повторная отправка одной и той же ссылки `/reset-password/:token` дважды подряд — мок не одноразовый, оба раза показывает успех (ожидаемо для этой стадии, одноразовость — 009)
- Смена языка на экране «Проверьте почту» — текст переводится, экран не откатывается к форме
- Открыть модалку удаления, переключить тему прямо во время открытой модалки — фон и карточка модалки остаются читаемы в обеих темах
- Клик по email в шапке на мобильной ширине (320px) — попадание по ссылке, а не по соседней кнопке «Выйти»
- Два быстрых клика по «Удалить» в модалке подряд — не должно навигировать дважды или дважды дёргать `logout()`
- Смена пароля в профиле и одновременно открыт `/profile` в другой вкладке (мок-сессия — сигнал в памяти конкретной вкладки, вторая вкладка ничего не узнает) — ожидаемое ограничение мок-стадии, не баг
